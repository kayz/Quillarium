# 界面皮肤契约

<p>
  <a href="UI-SKINS.md">English</a> · <strong>简体中文</strong>
</p>

本文定义 `0.3.1` 的界面皮肤边界。皮肤只能改变呈现，不能增加权限、修改项目数据、加载代码、访问
网络，也不能改变 AI 提示词。

## 兼容身份与存储

四个 ID 继续是 `paper`、`ink`、`mist` 和 `bamboo`。读取旧全局 `theme` 或项目
`default_theme` 时仍接受这些值。项目文件继续只保存兼容 ID；用户对皮肤的修改保存在本机
`~/.quillarium/config.json` 的 `uiSkins.customizations` 下。

没有 `uiSkins` 的旧配置只在内存中解析为产品默认值。读取、打开项目和预览皮肤都不会写迁移。作者
第一次明确保存时，才为当前槽位写入一份规范化的 V1 定义。“恢复内置”只删除当前槽位，不影响其余
三个皮肤的自定义。

## 结构化 schema

`UISkinDefinitionV1` 包含：

- 有长度上限的显示名称，以及四个稳定 ID 之一；
- 十四个六位十六进制颜色，覆盖应用、面板、文字、状态色和顶栏；
- 枚举化的界面/正文字体角色，以及限制在 90–115% 的字号比例；
- 枚举化的主导航位置、详情位置、工具栏排列和间距节奏；
- 枚举化的按钮形状、填充方式和尺寸。

它刻意不允许自由 CSS、HTML、JavaScript、URL、远程字体、图片路径或任意 selector。即使渲染进程
传来畸形数据，最终也由主进程调用的规范化函数把守边界。

## CSS 应用方式

渲染端把规范化定义映射为紧凑的 CSS token，例如 `--bg-panel`、`--interface-font`、
`--skin-panel-radius`、`--skin-button-height` 和 `--skin-toolbar-justify`。枚举化布局选择
转为 `data-skin-navigation`、`data-skin-detail` 和 `data-skin-button-treatment`；CSS 只改变
网格方向和视觉风格，不会重排项目文档，也不会改变 React 状态的所有权。
可调整分栏在面板显示到右侧时会反转鼠标与键盘增量，因此换边后拖动分界线仍符合实际空间方向。

四个产品默认皮肤不仅配色不同：

| 槽位     | 视觉性格       | 布局标识       | 按钮语言 |
| -------- | -------------- | -------------- | -------- |
| `paper`  | 温暖稿纸书桌   | 左导航、右详情 | 柔和实色 |
| `ink`    | 紧凑夜间工作区 | 左导航、右详情 | 方正同调 |
| `mist`   | 舒展蓝图工作室 | 右导航、右详情 | 胶囊描边 |
| `bamboo` | 编辑体竹青账簿 | 左导航、左详情 | 柔和同调 |

语言会和外观通过同一个类型化 IPC 保存，但仍是全局偏好。切换皮肤不会意外改变作者的界面语言。

## 可配置组件层

新的设置界面使用四个共享组件：

- `ActionButton` 负责语义色调和皮肤驱动的按钮几何；
- `ActionBar` 负责动作分组和皮肤/显式排列；
- `SurfacePanel` 负责面板底色、边框、圆角和内边距；
- `FormGrid` 负责响应式表单列数和间距。

旧功能组在逐步迁移期间继续使用兼容 CSS selector，因此皮肤可以立即影响现有按钮和面板，无需一次性
重写整个 renderer。宽度低于 860 px 时，表单和“编辑/预览”分栏收为单列；键盘焦点和减少动画仍由
产品代码拥有，不允许皮肤关闭。

## 保存与预览语义

编辑会把草稿即时应用到当前 document root。未保存就关闭设置时，恢复已持久化的皮肤和密度。保存
只调用一次 `config:saveAppearance`，同时发送皮肤、密度和语言；界面不再串行调用三个旧保存 IPC。
主进程返回的配置会再次解析并成为应用状态，因此最终可见结果与主进程接受的有界数据完全一致。
