# Quillarium：意图

<!-- spec 的第 1 层：只写代码表达不出来的东西。作者于 2026-11-08 确认本页的用户与模块划分。 -->

## 要解决的问题

作品里的事实（世界书、人物、时间线、伏笔、结构）和正文必须留在作者自己的纯文件里。AI 可以检查、提醒、整理和生文，但哪些文字和设定成为已接受的事实，由作者确认。Quillarium 按作品打开不同能力，而不是按一种用户做一套数据。

## 用户

用户差别是同一部作品上的能力组合。首页的新建作品向导用问卷写成五档之一：传统作家、AI 写手、AI 编剧、OC 人、AI 原住民。以后可以加角色，不加进已有五档的含义。一个人可以有多部作品，每部作品的能力各自保存。打开已有作品不问卷。交给用户时新建作品；用户权限与设定不为旧作品做兼容。

1. **传统作家。** 手写章正文。用系统管理设定、伏笔、世界书。AI 做问题检查和伏笔回收提醒。不使用节。最小文字单位是章。
2. **AI 写手。** 在传统作家的管理能力之外，关注桥段、结构和包袱。最小文字单位是节：围绕节拼装提示词、多次生成并选择，再合并进章。拆书是世界书导入的一种，规格见功能清单。
3. **AI 编剧。** 在 AI 写手之上，把一节或一章改写成约 1–2 分钟的短剧。交给外部工具的是资产提示词和分镜提示词。资产提示词带种子 ID，收回结果时用它对回本地资产。这一版不做。
4. **OC 人。** 不生文、不生图。拆书、扩库、整理和检查可以调用模型。精力在世界书和手绘图。作品停在章，展示层打开，可以上传图。
5. **AI 原住民。** 喜欢 OC，并接受全部生成式 AI，会大量使用生图。四个可选项全部打开：节与生文、展示层（含上传图）、生图、短剧导出。

## 模块

各模块可单独扩展。扩展不得改写其他模块的事实。模块内部再分层，能力开关挂在层上。界面按模块搭，不为角色另做一套壳。角色只打开或关掉可选模块；同一模块里的功能差异是多几个界面元素。用户权限与设定只服务新建作品。

- **用户权限与设定。** 管作者能用哪些层，以及本机上的界面设定。问卷和之后的修改都写在这部作品的能力记录上，不写进正文和设定卡。语言、密度、皮肤也在这里。模型、提示词和密钥不在这里，归 Agent。
- **世界书。** 设定事实的起点，下挂人物、地点、时间线、势力等特化。特化沿用同一稳定 ID。
- **结构树。** 写作页里的作品树。根是作品名称、简介和作品属性，其下是卷、篇、幕、章。新作品默认只显示卷和章。篇和幕在写作设置里打开，关闭不删文件。伏笔跨在这棵树外面，可以从世界书转过来，埋设和回收位置在这棵树上。节只在该作品打开节与生文时出现，挂在章下，是章的细分；生成用独立界面。全部节定稿后按顺序合并成这一章的草稿快照。
- **Agent。** 按场景持有任务、模型和提示词，并管理一次 AI 运行。Provider、公共提示词和模型选择属于这里。至少包括节的文字处理：提示词、生文、选择、修订。Agent 有自己的界面。密钥留在本机，不写入作品。
- **展示层。** 卡片上的 HTML 样式和图像。可以关闭，也可以按需生成。关闭后设定事实仍在。AI 生图是展示层里的单独能力，与手绘上传分开。
- **导入导出。** 与作品事实分开。当前适配器是 SillyTavern 的 CCv3 单向交换。以后对接其他系统时增加适配器，不把对方的结构写进核心文档类型。

## 当前目标

代码线仍是 `0.3.1` 本地候选版。作者于 2026-11-08 确认这一版做主体：两个主页面、五种身份、世界书、写作树、节、分段提示词和拆书。不为旧作品做设定迁移。地图画布、剧本设定、剧本资产、分镜和外部短剧工具不在这一版。

`0.3.1` 已在代码中的范围见 [ROADMAP](../ROADMAP.md#031-local-candidate-card-retyping-prose-extraction-and-ui-skins)：设定卡类型转换、从手写章正文抽取设定、拖入文件的用途选择、空白设定卡、四个界面皮肤，以及章中心骨架（可选的节、世界书特化、可关的展示层、只提案的专家模式、助手每轮一个确认层）。

## 不做什么

- 不把用户写作内容默认公开，不要求 Git 或 GitHub 账号。
- 不为某一类用户另建一套文档类型或平行字段。
- 不引入通用命令语言或任意脚本执行；插件平台推迟（见 ROADMAP 的 Deferred）。
- 短剧对接只产出提示词，不另造外部协议。这一版不实现。拆书按功能清单实现，不另造阅读器，也不把原文自动抄成正文。
- SillyTavern 只作为设计参考和可选格式适配边界，不是依赖，也不追求兼容。
- 流式输出与实时取消在相关 ADR 被接受之前不做。

## 关键决策

- 一部「作品」可以是小说、短剧或 OC 世界。作品数据以 Markdown/YAML 纯文件存放在 Obsidian 兼容的目录里；生成的索引和构建产物可丢弃。向导里仍问「写小说」或「写短剧」。首页副标题是「创造想象中的世界」。
- 能力记在新建作品上。问卷决定这部作品的初始能力。不为旧作品补记录或做设定迁移。
- AI 对项目和配置的任何写入都需要作者批准；助手对话不属于正设。
- 章正文依次经历草稿、定稿和不可变的已发布状态。手写章在节关掉时直接写。节打开时，生成发生在节的界面，完成后合并进所属的章。
- 节关闭时，作者直接写章。节打开时，一章的建议篇幅是 3000 到 6000 字，按大约 1000 字分成多节。字数是目标，不拦截保存。每节写情节、拼装提示词并单独生文；结果可以轮选、删除、修改、定稿。全部节定稿后按节序合并成这一章的草稿快照。之后改节要再合并。章定稿或发布后不能再合并。已有手写正文的章不被节覆盖。
- 问卷只开关四项：节与生文、展示层（含上传图）、生图、短剧导出。检查、整理、伏笔提醒，以及篇和幕，不由角色决定。生文只在节能力打开时存在。生图只在展示层打开时存在。OC 人不生文、不生图，其他模型调用不受这句限制。AI 原住民四项全开。
- 设定事实先进入世界书。事件、人物、地点、物品、组织、等级是世界书上的设定实体。正式事件要有人物、时间和地点，缺项只存草稿。多线是同一条时间线上的轨道。物品可以单独存在，重要道具只是标记，不自动成为伏笔。等级是一列档位，不另设开关。世界观和常识是条目上作者自己添加的字段，不单独成页，也不预置模板。伏笔由作者从世界书显性地转到写作页，转移后不再在世界书留一份同样的事实，位置在写作树上。地点这一版只保留层级。配图和卡面属于展示层，不写回设定事实。
- 生文提示词按段编辑。模板只保存段的种类和顺序，放在作品目录里。作者拖动后的顺序就是发送顺序。拆书默认只产生世界书提案；作者点选后才把正文导入为章草稿。
- 优先使用确定性检查，再用 AI 辅助检查。
- 版本 tag 和 GitHub Release 不可变，失败的版本不移动、不重跑，修复后用新的版本号（见 [RELEASING](RELEASING.zh-CN.md)）。
- 用户划分与模块所有权见 [ADR-work-audiences](adr/ADR-work-audiences.md)。其余架构决策见 [docs/adr/](adr/)。英文技术规格描述当前实现；与本页冲突时，以本页和该 ADR 的产品决定为准，文件行为以规格和测试为准，直到规格被另行更新。

## 验收入口

- 桌面端：`pnpm desktop:dev`。传统作家路径：进入写作，手写章，检查、定稿、发布、导出，不出现节；拆书、扩库和整理仍可用。节能力打开的路径：在章下按节生成、轮选、定稿，全部定稿后合并成这一章的草稿。OC 人进入世界书，不出现节、生文、生图和短剧导出，可以上传图片、导出卡片，也可以拆书。AI 原住民路径四项都出现。检查与整理在五档都出现。
- 命令行：`pnpm cli --help`。
- 自动化：`pwsh -NoProfile -File scripts/check-fast.ps1`；验收测试在 `tests/`。
- 安装包签名以及全新 Windows/macOS 机器验收仍是人工门禁。
