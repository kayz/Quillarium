# 以章为中心的产品骨架

Date: 2026-09-21  
Status: approved  
Scope: 产品主线、模块边界、节/生文、世界书特化、展示层、Agent 职责。不包含具体改文件清单。第一份施工计划见 `docs/superpowers/plans/2026-09-21-scene-module-chapter-commit.md`。

## 主线

Quillarium 是 **本地长篇小说写作管理** 工具。主用户是作家。

作家核心能力：

- 篇章结构（把书拆成可写的块）
- 世界观细化（世界书 → 特化卡片，以及该类型的管理）
- 伏笔等专项内容的管理

OC 用户是 **轻度用户**：同样可以使用世界书，并特化成人物、地点等卡片。他们与作家的产品差别主要在 **展示层**（界面友好、图片/卡片视觉），不在数据模型。展示层封装交互复杂性，用户按项目自由开关。

## 产品骨架

其它能力都是挂在「以章为中心的写作」上的模块，不能反过来决定树怎么长。

```text
卷
  └ 篇（可选）
       └ 幕（可选）
            └ 章     ← 主单位：章纲 + 章正文
                 └ 节模块（项目级可选；模块内部再拆节）
```

五个模块：

1. **世界书与特化设定** — 卡片事实与类型管理。作家核心，也是设定能力以后扩展的地方。
2. **结构树** — 只负责把书拆成可写的块。默认：卷 →（篇）→（幕）→ 章。
3. **节 / AI 生文** — 挂在章上。把一章拆成约 1000 字的节，生成后再汇总成章正文。
4. **展示层** — 挂在卡片上。不改卡片事实。打开后服务更友好的视觉与交互（含 OC 体验）。
5. **Agent 专家模式** — 整理大纲和世界书、分析漏洞和关系、管理伏笔等、评估章正文并补充设定。产出是提案，写入须作者确认。

### 两条 AI 必须分开

| | 专家 Agent | 节-生文模块 |
|---|---|---|
| 谁用 | 作家主路径 | 可选；OC 也会愿意用 |
| 作用 | 评估、整理、补设定 | 从章纲拆节，生成章正文 |
| 是否写正文 | 否 | 是（须作者确认后，在全章节完成时写入） |
| 实现 | Agent 专家模式 | 独立模块，不并入 runtime 来「统一生成」 |

## 节 / AI 生文模块

节的核心是为 AI 生文做准备，不是故事树上必须存在的一层。

未启用该模块时：作者直接写章正文。树停在章。

启用后，对 **当前这一章** 做四件事：

### 1. 拆节并写节纲

把本章进一步分拆。每一节有 **节纲**。节纲即该节的生文提示词（作者要写的「这一节写什么」），不是另一套与生成无关的大纲格式。

目标粒度：每次生文约 **1000 字**。

### 2. 准备本节完整提示词

根据：

- 章纲
- 本节节纲所描述的场景
- 本节涉及的卡片（世界书及其特化：人物、地点等）
- 之前的章节：各层纲要（卷/篇/幕/章）以及 **最近的正文**

组成一条完整提示词，再交给模型生文。

上下文装配必须仍是确定性、可解释的（现有 ContextTrace 方向保留），但 **服务对象是节模块**，不是把节做成与章平级的交付物。

### 3. 多次生文与作者控制

支持：多次生成、候选选择、手工修改、局部改动、确认。未确认不写入章正文。

### 4. 全章完成后才输出

**这一章的所有节都完成后**，将各节已确认正文按节序写入 **章正文**。这是本模块的输出。

与当前实现的差异：现在是「每接受一节就立刻追加进章正文」。规划改为 **整章节齐了再写章正文**，避免半章生成态和手写章正文缠在一起。

磁盘上的节工作件（节纲、候选、run）在模块关闭后可以保留，但不进入写作主界面。

## 世界书 → 特化类型

所有卡片类内容 **首先是世界书**。内容足够细之后，再特化到人物、时间线、地点、伏笔等。

特化之后，按类型提供管理方式，例如：

- 人物：关系
- 时间线：顺序与显示
- 伏笔：埋设与回收

这一块是作家核心，也允许以后加新的特化类型和管理方式。 **扩展发生在类型管理，不发生在写作树，也不为 OC 单独加一套文档类型。**

OC 也可以把世界书特化成人物、地点等。不是「OC 只能停在未特化的世界书」。

## 展示层

展示层是卡片上的 **独立模块**，**项目级可选**。

- 选中后，挂载在各类卡片上（世界书及特化后的人物、地点等）。
- 展示层本身可以扩展（图片、HTML 设定卡等），用来降低交互复杂度、丰富轻度用户体验。
- 关闭展示层：卡片事实仍在，管理方式（关系、时间线、伏笔）仍在，只是没有那套视觉/交互外壳。

展示层不得要求新的写作字段才能工作；不得成为打开项目或开始写章的前置。

## Agent 专家模式

开发核心是 Agent 的专家模式，职责限于写作支持，不写正文：

- 引入并整理大纲和世界书
- 分析设定漏洞和关系
- 管理人物、伏笔等专项内容
- 对章正文做评估，并提案补充设定

每一项可执行写入仍须作者确认。现有 `agent-runtime` 的收口按这个边界：检查/整理/评估类任务属于这里；生文不硬迁进来。

## 非目标

- 不为 OC 新增平行的文档类型或字段。
- 不把生文、助手对话、导入全部塞进同一个 runtime 才算「完成 Agent」。
- 不让展示层、CCv3、皮肤成为写作树或章正文的前置。
- 本文不是重构施工清单（文件级任务在规划确认后另写）。

## 与现状的主要偏差（供后续实施方案使用）

- 当前设计文档把 **节定为最小 AI 生成单位**，并与章并列在树上。规划改为：节只在可选模块内存在，交付单位始终是章。
- 当前接受一节即写入章正文。规划改为全章节完成后再写。
- 当前 Agent 任务目录与生文编排双轨。规划改为专家模式与生文模块分家，不再追求生成路径迁入 runtime。
- 当前展示/图片/HTML 卡与设定模型长在一起。规划改为展示层可关，特化与类型管理留给写作。
