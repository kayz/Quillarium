# 作品上的用户能力与模块所有权

状态：已采纳

## 背景

2026-09-21 的产品骨架把主用户定为作家，把节定为可选生文模块，把章定为唯一交付单位。2026-11-08 作者确认五档：传统作家、AI 写手、AI 编剧、OC 人、AI 原住民。角色只开关四项：节与生文、展示层（含上传图）、生图、短剧导出。OC 人不生文、不生图；拆书、扩库、整理和检查仍可调用模型。AI 原住民四项全开。差别在能力，不在文档类型。若按用户分叉存储，作品文件会变成两套。

当前实现已经有作品级的 `story_structure`（篇、幕、节开关）和可选的 `display_layer`。世界书特化、专家任务、节生文、展示图和 CCv3 交换也已分别落在 `@quillarium/core`、`@quillarium/agent-runtime`、`@quillarium/ai`、`@quillarium/sillytavern`。没有启动问卷，没有作品级的“用户类型”记录，生图没有单独开关，伏笔管理没有归到结构树表面，Provider 仍在设置里而不是 Agent 自己的界面。拆书的产品规格已记在功能清单，代码尚未实现。短剧对接的格式是资产提示词和分镜提示词，资产要拿回种子 ID；这一版不实现。

## 决策

- 持久化的是一部作品的能力，不是账号上的用户类型。问卷在创建作品时给出初始能力。交给用户时新建作品；用户权限与设定不为旧作品补记录或做迁移。
- 传统作家：四项全关，章为手写正文单位。AI 写手：只开节与生文。AI 编剧：开节与生文、短剧导出。OC 人：只开展示层和上传，停在章。AI 原住民：节与生文、展示层、生图、短剧导出全部打开。检查、整理、伏笔提醒以及篇、幕不写入这五档。
- 2026-11-08 补充：作品内的导航只有世界书和写作。节是章的细分：一章一般 3000 到 6000 字，按大约 1000 字分成多节分别生文。全部节定稿后合并成这一章的草稿快照；章定稿或发布后不能再合并。伏笔跨在篇章树外，从世界书显性地转入写作，埋设和回收位置在写作树上。细节验收以功能清单为准。
- 2026-11-08 再补充：这一版做主体。拆书默认只产生世界书提案，作者点选后才导入正文。生文提示词按段编辑，模板只保存段的种类和顺序。物品和等级是作者确认的设定实体。地图画布、剧本设定、剧本资产、分镜和外部短剧工具这一版不做。分镜以后仍是节的再拆分：一节约 1–2 分钟，按 5–15 秒的视频生成长度切开。对接的最终格式是资产提示词和分镜提示词。资产提示词带种子 ID，收回结果时用它对回本地资产。
- 模块所有权为：用户权限与设定拥有问卷、作品能力记录，以及语言、密度和皮肤；世界书拥有设定事实和特化；结构树拥有大纲、章/节正文生命周期，以及伏笔的管理表面（伏笔文件不搬家）；Agent 拥有任务、Provider、公共提示词、模型选择和运行记录，并有自己的界面，密钥留在本机；展示层拥有卡面和图像，生图是否允许由作品能力决定；导入导出只通过适配器接触外部系统，现有适配器是 CCv3。
- 新作品用附加字段记下能力。不为旧作品缺字段补写。禁止为了新用户类型另建一套 Markdown。
- 拆书按功能清单实现，不另建文档类型。短剧对接只产出提示词，不增加外部协议文件类型。物品和等级是作者确认后增加的设定实体。除此之外不增加文件类型。
- 不把 `@quillarium/core` 按模块拆包，直到某一模块的变更节奏确实与其余部分分开。包之间继续只通过公开入口依赖。

本决定取代 2026-09-21 骨架里“只有一类主用户”和“章永远是唯一文字单位”这两句。文件格式、哈希写入和“AI 写入必须经作者确认”保持原决定。

## 后果（包括放弃了什么）

- 同一作者的不同作品可以一个手写、一个生文，数据模型仍然一套。
- 英文规格里凡把节写成全体用户的默认写作层、或把展示图写成设定的一部分，在产品含义上让位于本决定；改代码前以规格和测试描述当前行为。
- 放弃按用户类型复制世界书或结构树。拆书已有规格。短剧对接的格式已经定为提示词，实现仍推迟。
- 设置页里的模型配置最终改由 Agent 界面拥有；语言、密度、皮肤和作品能力归用户权限与设定。在界面分开之前，现有设置页继续有效。
