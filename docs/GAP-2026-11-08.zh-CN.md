## 候选版还没关闭

这些是把 `0.3.1` 从“本地候选”变成“已发布”之前的缺口：

- 包版本已经是 `0.3.1`（根目录和各 package 的 `package.json`），Git tag 仍停在 `v0.3.0`。`v0.3.1` 按发布规则还不存在，这是对的；版本号已经提前写上。
- `docs/releases/v0.3.1-acceptance.zh-CN.md` 从“准备”到“发布前确认”全部未勾。清单自己写明：全部勾完才创建 tag。
- 发布流程里的安装包签名、全新 Windows/macOS 机器、重启、凭据和无障碍检查没有本次记录。
- `docs/README.zh-CN.md` 开头仍写导航对应已发布的 `v0.3.0`。候选能力写在后面的“本地候选版”一节，读者容易把工作区当成已发布版本。

## 规范文本落后于代码

英文规范是唯一技术契约。下面几处契约和 `46e421b` 的代码不一致，后续改行为时会按过期描述决策。

1. `docs/AGENT-DESIGN.md` 仍写“截至 2026-08-17，runtime 只承接项目级规划完整性检查”。同一文件列出的导入、规划对话、正设协作、节生文、语义检查、定稿评审、创作助手“仍走各自编排”。代码里专家任务和两张卡面设计任务已经进了 `AgentTaskRegistry`。
2. `docs/DESIGN.md` 的 Implementation Status 开头仍以 2026-08-19 的 `v0.3.0` 为主语。`0.3.1` 的转类型、正文抽取、皮肤写在后文 “Unreleased”，runtime 段落仍把“项目检查是第一个迁移流”当作现状全貌。
3. `docs/intent.md` 规定：流式输出和 provider 确认的实时取消，在相关 ADR 被接受之前不做。桌面已经有 `apps/desktop/electron/ipc/ai-stream.ts` 的开始/阶段/增量/完成事件，以及 `ai:cancelStream`。导入和规划对话通过 `withDesktopAIStream` 使用它。`DESIGN.md` 仍写流式和实时取消不属于 runtime 第一轮。目前没有一份被接受的流式 ADR。这条是意图、设计和代码三方不一致，不是“功能缺失”。

`docs/superpowers/` 里各规格的“与现状的差”是 2026-09 施工前的记录。那些差已经反映进上面的代码入口，不要再把那些小节当成未做清单。

## 统一 Agent Runtime

ADR `docs/adr/ADR-unified-ai-agent-runtime.md` 的目标是：每一次模型调用都经过 `@quillarium/agent-runtime`。P0 当时只迁移了项目级规划检查，并写明其余清单以后逐个迁移。9 月的专家任务和卡面设计已经接上 runtime。下面这些调用仍在 runtime 之外，直接使用 `@quillarium/ai`：

| 产品流                   | 当前位置                                                               |
| ------------------------ | ---------------------------------------------------------------------- |
| 资料批量导入与卡片再抽取 | `apps/desktop/electron/ipc/import.ts` 调用 `generateText`              |
| 规划卡多轮对话           | `apps/desktop/electron/ipc/planning.ts` 把 `generateText` 当作生成函数 |
| 正设协作                 | `apps/desktop/electron/ipc/canon.ts` 调用 `generateCanonText`          |
| 节生文                   | `apps/desktop/electron/ipc/scene.ts` 调用 `generateText`               |
| 节语义检查               | 同上，以及 `packages/cli/src/index.ts` 的 `check --semantic`           |
| 章定稿评审的模型调用     | `scene.ts` 的 `finalize:reviewPlan`                                    |
| 三个创作助手的对话轮     | `apps/desktop/electron/ipc/assistant.ts` 调用 `generateStructured`     |

节生文留在 runtime 外面，是 `docs/superpowers/specs/2026-09-21-chapter-centered-product-design.md` 已经锁定的决定：生文只在节模块里，不为了“统一”而并进 runtime。这不是漏迁移。

助手的**确认写入**已经是 `applyAssistantTurn`。助手的**模型调用**仍是旧会话编排。确认层和执行边界是两件事。

ADR 还要求：Desktop IPC 和 CLI 迁移完成后，禁止它们直接调用 provider。这道仓库门禁现在还不能加，因为上表里的直接调用还在。

## 路线图标明尚未开始

这些写在 `ROADMAP.md` 的 P1、P2 和 Deferred，也写在 `intent.md` 的“不做什么”里。它们不是 `0.3.1` 的欠账。

P1（可审计的生命周期和记忆）：

- 发现 Obsidian、外部编辑器或 Git 改过的项目文件，并露出过期会话冲突。现有“stale hash”是写入前的哈希拒绝，不是外部变更监视。
- 长任务可暂停、可恢复的提问/批准总线。
- 在独立 ADR 接受部分输出持久化、取消确认、重试安全和 UI 归属之后，再做正式流式和 provider 确认的实时取消。
- 已提交的核心操作发出强类型事件（`context.assembled`、`candidate.selected`、`scene.accepted`、`finalization.applied`）。`DESIGN.md` 写明当前 core 没有事件总线。
- 带显式过期时间的写作笔记。
- 可重建、引用源章、且不能替代已接受正文的滚动摘要。
- 把发布反馈接回章级回顾和后续规划。

P2：权限受控的声明式章节配方（装配上下文、生成候选、检查、比较、接受节、检查章、定稿）。不是通用命令语言。

推迟：插件平台。任意 JavaScript 安装不在范围内。

`intent.md` 里已经生效、代码也没有违反的边界：不默认公开作品，不要求 Git 或 GitHub 账号，SillyTavern 只做可选的 CCv3 格式边界。
